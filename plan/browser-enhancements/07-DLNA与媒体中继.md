# 07 DLNA 与媒体中继

## 基线、目标与依赖

基线为 `origin/main@ca904c36ff6bede07ab8092dde16e9903a41a7c8`，应用版本 `0.1.9+7`。依赖 `04` 的媒体授权、`05` 的缓存资源和 `06` 的 MP4 交付资源。

目标是在 Android 支持一个 DLNA 投屏会话，并为接收端无法直接访问的已批准媒体提供受控中继。非目标是任意 URL 代理、把设备返回的 URL 自动升级为授权上游、实时转码和多会话并发。

## 设备与会话模型

- 固定版本 UPnP/DLNA 组件；先覆盖相对控制地址、服务版本、SOAP 错误和 `GetProtocolInfo`。
- `CastDevice` 只记录设备能力；`CastSession` 绑定设备、媒体来源、状态和中继令牌。
- 状态：`发现 → 连接 → 设置媒体 → 播放/暂停 → 停止/失败`；同一时刻一个会话。

## 直连、中继和安全

- 接收端可直接访问的公共媒体优先直连。
- 需要 Cookie、Referer 或本地缓存时使用应用中继；中继只接受已批准媒体任务，绑定目标设备和短期令牌。
- MP4 中继支持 HEAD、Range、正确长度和状态码；HLS 中继重写主/变体清单、分片、初始化资源和密钥地址。
- 浏览凭据只用于应用取源，不能发送到电视/盒子；会话停止、网络切换、令牌过期或进程退出都撤销中继。

## 执行步骤

1. 固定组件版本并建立发现、连接、SOAP、能力解析和错误映射。
2. 实现单会话控制、设备能力展示和用户主动投屏动作。
3. 实现公共 MP4 直连；对授权缓存/远程媒体启用短期令牌中继。
4. 实现 Range/HEAD、HLS 多级清单与密钥地址重写，拒绝任意 URI。
5. 处理来源标签关闭、熄屏、网络断开、设备离线、令牌过期和进程退出。
6. 接收端不支持 HLS 时提示先使用 `06` 导出 MP4；不做实时转码。

## 计划测试与验收（本轮不执行）

- 实际电视/盒子发现、连接、播放、暂停、跳转、停止和音量（按能力）。
- 公共 MP4 直连、鉴权 MP4 中继、缓存文件投屏、HLS 全链路中继。
- 设备离线、网络断开、熄屏、权限拒绝、令牌失效和会话恢复。
- 必须有接收端实际播放证据；SOAP 成功或本地 HTTP 200 不能单独视为通过。

输出：设备/会话 DTO、直连与中继授权规则、Range/HLS 中继边界和真实设备证据模板。禁止在本阶段扩展为通用代理或实时转码。
