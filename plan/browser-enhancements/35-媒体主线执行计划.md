# 媒体主线执行计划

日期：2026-10-25  
当前实现基线：`codex/media-alpha1`，`0.5.0-alpha11+109`  
验证设备：`emulator-5554`  
主线范围：观看保存、共享媒体缓存、HLS 边下边播、原生后台播放与系统控制、HLS/MP4 导出与媒体所有权、后台授权刷新。

## 1. 目标和边界

媒体主线的结果是：用户从当前正在播放的网页得到一条可追踪的观看保存记录；相同内容在观看保存、手动下载、原生播放、导出和投屏之间复用已经提交的媒体字节；HLS 在下载完成前可以由原生播放器消费；Flutter 页面被销毁后媒体任务和原生会话仍有明确的生命周期；授权失效时只在原页面和同一媒体身份范围内受限刷新；删除任一消费者时不会误删仍被其他消费者使用的文件。

本计划不把以下事项作为本轮媒体主线的完成条件：DRM 解密、付费墙/会员权限/验证码/登录绕过、网页内部请求与保存器的零重复复用、直播录制、MSE/blob 自动还原、跨设备账号同步。DLNA 本机 relay 作为媒体所有权的下游使用方保留验收入口，真实电视/盒子是独立设备门禁。

媒体产物分成三层：

1. 应用内部共享缓存：由资源身份、分片索引、提交状态和 owner/lease 管理，服务边下边播、重播、导出和投屏。
2. 已校验的 HLS 资源：保留 m3u8、init/MAP、分片、key/Range 关系和本地资源索引，作为可继续播放和导出的原始输入。
3. 独立 MP4 artifact：由完整 HLS 资源经过 Media3 Transformer/Inspector 生成，拥有独立 catalog 身份和生命周期。

## 2. 权威边界

- Flutter 负责产品状态、用户意图、观看保存展示、任务列表和诊断展示。
- Android 原生负责 MediaSessionService、ExoPlayer、后台执行、系统通知、文件读写许可、授权刷新 WebView 和原生文件 lease。
- HLS 资源身份必须包含来源、内容/剧目、集数、清晰度、音轨、表示形式和内容版本；临时 token、签名和 cookie 只属于授权上下文，不能单独改变内容身份。
- 已提交文件才可被播放器、导出器或 relay 读取；`.part` 只能由当前 writer 使用。
- 取消、暂停、删除 owner 与资源传输分离。最后一个 owner、最后一个读写 lease 都释放后，才允许回收共享资源。
- `waiting_execution` 表示系统暂时没有可用执行环境；`reauthorize` 表示已执行受限刷新但无法证明同一媒体身份。两者不能混为授权失败。

## 3. 状态和最小数据模型

每个媒体任务至少同时维护以下维度，禁止用一个状态字符串代替全部语义：

| 维度 | 最小状态 |
|---|---|
| 播放证据 | `observed`、`confirmed`、`revoked` |
| 观看保存 | `playing`、`paused`、`ended`、`stale` |
| 传输 | `queued`、`downloading`、`paused`、`waiting`、`completed`、`failed`、`cancelled` |
| 可用性 | `empty`、`partial`、`complete`、`invalid` |
| 授权 | `valid`、`refreshing`、`waiting_execution`、`reauthorize` |
| 导出 | `none`、`queued`、`exporting`、`validating`、`ready`、`failed` |

最小实体：`PlaybackEvidence`、`WatchSaveOwner`、`MediaAsset`、`MediaRepresentation`、`HlsManifestSnapshot`、`HlsResourceEntry`、`TransferJob`、`MediaLease`、`ExportArtifact`。物理表可以合并，但必须保留唯一键、事务边界、执行 epoch 和恢复规则。

## 4. 子计划和依赖

```text
M0 基线/契约/迁移护栏
 ├─ M1 观看保存与播放身份
 ├─ M2 共享资源、owner、lease、单 writer
 │    └─ M3 HLS 部分缓存与传输调度
 │          ├─ M4 原生后台播放器与系统控制
 │          └─ M5 HLS/MP4 导出与 artifact 生命周期
 └─ M6 后台授权刷新

M1 + M2 + M3 + M4 + M5 + M6
 └─ M7 UI/诊断/故障证据
      └─ M8 emulator 门禁、APK、真机流程和发布记录
```

M1 和 M2 在 M0 后可以并行；M4 的服务骨架可和 M3 并行，但接入部分缓存播放器必须等待 M2/M3 的读 lease 和提交索引；M5 必须等待 M2 的资源所有权；M6 可和 M3 并行，但后台补齐只能在 M3 的队列和暂停原因稳定后开启。

## 5. 最小执行单元

### M0.1 当前基线和证据冻结

**目的**：把旧计划、当前未提交实现和新验收范围分开，避免用历史 alpha 证据覆盖新代码。

**检查/变更**：

- 固定 branch、pubspec 版本、Android package/versionCode、Media3 版本和验证设备。
- 保留现有 `docs/streaming-and-settings-plan.md`、`docs/native-background-playback-plan.md` 的历史内容；本文件作为当前主线索引。
- 为每个子计划登记代码路径、测试命令、设备命令和直接证据。

**退出条件**：工作树状态、基线提交、APK 身份和测试设备均可复现；任何历史证据都带有原始版本和设备边界。

### M0.2 契约和迁移护栏

**代码范围**：`lib/domain/models.dart`、`lib/data/database.dart`、`pigeons/web_host.dart`、生成的 host bindings、`android/app/src/main/kotlin/dev/vikiea/site_lens/`。

**执行单元**：

1. 固定 `PlaybackEvidence` 的 frame/document/epoch/source/episode/representation/eventSequence 字段。
2. 固定 `resourceKey`、`ownerId`、`leaseId`、`executionEpoch` 的格式和唯一性。
3. 旧 `media_tasks`、旧 `.hls.part`、旧 `resources.json` 和 Worker 状态只能迁移或只读投影，不能和新 writer 竞争。
4. 为未知、冲突、旧版本、损坏 sidecar 保留原字节并返回结构化原因。

**测试**：数据库迁移、旧备份、身份冲突、重复导入、时间戳排序、旧 epoch 迟到写入。

**退出条件**：新字段缺失可安全读取；旧数据不被静默拼接、删除或重新认领；契约测试先于后续实现合入。

### M1.1 播放证据采集

**代码范围**：`web_assets/media_lifecycle.js`、`android/.../NativeWebHost.kt`、`lib/web_host/native_hosts.dart`、`lib/ui/app_controller.dart`。

**执行单元**：

1. 页面只上报当前 frame/document/SPA 代次、真实媒体元素/源、播放状态和结构化身份线索。
2. Dart 只在同代候选已经持久化、唯一匹配且没有 route/host 失效时确认。
3. pagehide、换页、frame 替换、A→B→A、旧 eventSequence 和迟到 clear 必须撤销旧确认。
4. 推荐元素、AudioContext、只出现 timing 的候选、同 URL 多集冲突均只能进入 `unknown`。

**测试**：`test/native_hosts_media_test.dart`、`test/watch_save_controller_test.dart`、`tool/test_media_lifecycle.mjs`、页面导航和 frame 回归。

**退出条件**：没有“候选出现即等于正在播放”的路径；当前选中标签之外的页面不能创建自动观看 owner。

### M1.2 观看保存 owner 和 stale guard

**代码范围**：`lib/media/watch_save_store.dart`、`lib/domain/models.dart`、`lib/data/database.dart`、媒体管理 UI。

**执行单元**：

1. 用稳定的内容/表示身份和观看 owner 幂等创建记录。
2. 进度、时长、播放状态和事件序号原子保存；旧 snapshot/eventSequence 不能回退新进度。
3. 暂停、结束、离页和删除记录不自动删除媒体任务、共享缓存或独立 MP4。
4. 清晰度/音轨/内容版本变化生成新资源，不覆盖旧资源。

**测试**：watch save store 单测、控制器单测、重启恢复、跨 tab、暂停/恢复/删除回归。

**退出条件**：同一集只产生一个观看 owner；删除观看记录不会影响其他 owner。

### M2.1 资源身份和共享索引

**代码范围**：`lib/data/database.dart`、`lib/domain/models.dart`、`lib/media/media_service.dart`。

**执行单元**：

1. 由稳定内容/表示身份生成 `resourceKey`，保留必要选择参数。
2. 记录 `media_resources`、`media_resource_owners` 和任务到资源的映射。
3. 观看保存、手动下载、原生播放、导出和 relay 添加 owner 时复用同一资源。
4. 临时授权变化只更新授权代次；无法证明同身份时创建新资源。

**退出条件**：同资源只保留一份已提交字节；不同集数、清晰度、音轨和未知身份不会错误合并。

### M2.2 单 writer 和跨调用 lease

**代码范围**：`lib/media/media_resource_coordinator.dart`、`android/.../NativeMediaFileLeases.kt`、`NativeMediaDownloadWorker.kt`、删除/移动/导出入口。

**执行单元**：

1. `.part`、原子发布、lock 目录、owner heartbeat 和过期 lease 恢复。
2. 同一资源的并发请求合并为一个 writer；后来的消费者等待已提交文件。
3. 删除先检查所有 owner/reader/writer lease；最后 owner 才能触发回收。
4. Activity、Flutter Engine、Worker 和 MediaSession 的迟到回调必须带 execution epoch。

**测试**：`test/media_resource_coordinator_test.dart`、原生 JVM lease 测试、删除/移动/导出竞态、进程重启和故障注入。

**退出条件**：并发 writer 数量为 1；正在读的文件无法被删除、移动、覆盖；写入失败保留断点。

### M3.1 传输调度器

**代码范围**：`lib/media/media_transfer_scheduler.dart`、`lib/media/media_service.dart`、原生传输 Worker。

**执行单元**：

1. 活跃媒体资源任务上限为 4。
2. 原生播放和 seek 缺片最高优先级；当前观看保存次之；旧集后台补齐最多 3 集。
3. 普通任务按等待时间老化，避免长期饥饿。
4. 网络限制、空间不足、用户暂停、系统不可执行必须唤醒等待者并保留原因。

**退出条件**：并发上限、优先级和公平性有单测；没有依赖 Dart Timer 才能恢复的核心状态。

### M3.2 HLS 增量清单和资源提交

**代码范围**：`lib/media/media_service.dart`、`lib/media/native_media_runtime.dart`、HLS parser/validator、`NativeMediaRuntime.kt`、`GrowingFileDataSource.kt`。

**执行单元**：

1. 固定 VOD manifest、相对 URI、MAP/init、AES-128 key、Range 和 ENDLIST 关系。
2. 首个已提交分片到达后写入稳定路径下的本地 playlist，不能在播放开始后重命名目录。
3. 播放器读取不到的分片向协调器提升请求；未缓存 seek 有界等待，超时转为可恢复错误。
4. 请求顺序可以重排，但本地 playlist 顺序、时间线和最终 EOS 必须保持原始顺序。
5. 已提交资源不重复下载；旧 `.part` 只有在身份、validator 和长度均匹配时续传。
6. 原生本地 DataSource 对已发布但暂时不可读的分片进行有界等待；不读取 `.part`，不回源，不绕过 owner/lease。

**测试**：慢速 TS/fMP4/AES-128 fixture、首片早播、未缓存 seek、目标分片优先、取消/恢复、回看不重复下载、EOS。

**退出条件**：`MEDIA_PARTIAL_PLAYBACK_PASS`、`MEDIA_HLS_SEEK_PRIORITY_PASS` 和完整 HLS 资源校验均通过；不把“首片可播”报告为下载完成。

### M4.1 原生 MediaSessionService

**代码范围**：`android/.../NativeMediaSessionService.kt`、`NativeMediaRuntime.kt`、`MainActivity.kt`、Manifest、Pigeon/MethodChannel bridge。

**执行单元**：

1. application context 持有 ExoPlayer/MediaSession；Activity/Flutter 只持有 surface 和命令桥。
2. 打开前取得读 lease；切换时新资源先取得 lease，旧资源在播放器释放后再退租。
3. Activity/Engine detach 不停止服务；显式停止、错误、系统回收和 service destroy 走统一屏障。
4. bridge 重建只能重新绑定同一 session/epoch；旧页面的 close/detach 不能停止新 session。

**测试**：原生契约、MediaSession rebind、Surface detach/attach、重复播放器和读 lease 回归。

**退出条件**：Flutter bridge 重绑保持同一会话；页面销毁不会误停止当前原生播放。

### M4.2 通知、锁屏和系统控制

**代码范围**：Media3 notification、`AndroidManifest.xml`、`tool/android_media_actions.py`、integration tests。

**执行单元**：

1. 通知显示当前媒体和可用动作；播放、暂停、seek、上一/下一集、停止映射到同一 Player。
2. 用户暂停意图与底层 buffering 分离，避免缓冲误显示为用户暂停。
3. 音频焦点、耳机拔出、锁屏、通知权限关闭和系统限制都返回具体状态。
4. 停止后通知清理、session 关闭和 lease 释放可观察。

**退出条件**：模拟器可自动验证系统控制；真实设备必须补锁屏、通知栏、耳机和系统省电证据。

### M5.1 完整 HLS 和 MP4 导出

**代码范围**：`android/.../NativeExportRuntime.kt`、`native_export_runtime.dart`、`media_library.dart`、`Media3ExportValidation.kt`。

**执行单元**：

1. 仅完整、已校验的 HLS 输入允许进入导出；部分缓存、缺片、未知 key/Range 和越界路径拒绝。
2. 复用 Media3 Transformer/Inspector；只允许 transmux，不隐式编码或回源。
3. 保持视频 decode order、B-frame PTS、AAC access unit、ASC/ADTS、EOS 和样本计数。
4. 输出写入 `.part`，校验通过后原子发布并登记独立 catalog/artifact。

**退出条件**：`MEDIA_TASK_LIFECYCLE_PASS`、`NATIVE_REMUX_PASS`、连续播放/seek 和输出完整性通过。

### M5.2 所有权、删除和媒体库恢复

**代码范围**：`lib/media/media_library.dart`、`NativeMediaFileLeases.kt`、删除/移动/重扫逻辑、数据库迁移。

**执行单元**：

1. MP4 artifact 与源 HLS task 独立登记；删除 task 不删除 artifact。
2. 源 HLS 只有在没有 owner、reader、exporter、caster lease 时才回收。
3. 删除、移动、复制、SAF 投递使用校验复制和可恢复记录；Engine 消失后可重试。
4. catalog 丢失时扫描已发布文件恢复索引，保持内容身份和移动后的 catalog ID。

**退出条件**：独立 MP4、源 HLS、共享资源和媒体库索引的删除/恢复回归均通过。

### M6.1 后台授权刷新

**代码范围**：`NativeMediaAuthRefreshService.kt`、`lib/media/native_media_auth_refresh.dart`、`NativeMediaDownloadWorker.kt`、`MainActivity.kt`。

**执行单元**：

1. 使用原 profile/cookie 的隐藏 WebView；cookie、Authorization、Storage 不跨桥明文返回。
2. 只允许原页面、同剧/同集/同清晰度/同音轨/同内容身份范围；禁止跨站顶层跳转、弹窗、外部 intent、脚本和自动播放。
3. 首次确定的 401/403 最多自动刷新一次；刷新成功必须重新校验 manifest、分片、MAP/key、轨道和内容身份。
4. 没有后台执行环境返回 `waiting_execution`；实际失败进入 `reauthorize`，保留断点和旧缓存。
5. 当前集和旧集都遵守保存开关、网络限制、并发预算和用户强制停止语义。

**退出条件**：`MEDIA_AUTH_REFRESH_PASS` 通过；同源、cookie 不出桥、失败可人工重授权、无候选污染均有证据。

### M7.1 状态、诊断和错误可见性

**代码范围**：`lib/ui/media_tasks_screen.dart`、`lib/ui/filter_diagnostics_panel.dart`、`lib/diagnostics/error_log.dart`、native error mapping。

**执行单元**：

1. UI 显示任务、资源、owner、lease、下载/可播/授权/导出状态和暂停原因。
2. 记录规则/脚本/传输/授权错误的具体 code、resourceKey、taskId、execution epoch 和时间。
3. `waiting_execution`、`reauthorize`、`unsupported`、`disk_full`、`network` 分开显示。
4. 诊断页只读；打开诊断不能创建 WebView、发起授权刷新或启动下载。

**退出条件**：页面异常时可定位命中资源/任务/脚本错误；敏感 header、cookie 和私有 URL 不进入日志。

## 7. 禁止的完成推断

- 模拟器通过不能推导任何真实设备后台、锁屏、codec 或省电策略通过。
- MediaSession bridge rebind 不能推导进程被杀后恢复通过。
- 本机 DLNA relay 返回完整文件不能推导电视/盒子实际播放、暂停或 seek 通过。
- MP4 remux 通过不能推导 DRM、会员权限、验证码、登录绕过或含 key HLS 通过。
- `waiting_execution` 不得显示成授权失效；`reauthorize` 也不得静默换候选。
