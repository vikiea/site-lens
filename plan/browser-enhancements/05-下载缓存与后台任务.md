# 05 下载缓存与后台任务

## 基线、目标与依赖

基线为 `origin/main@ca904c36ff6bede07ab8092dde16e9903a41a7c8`，应用版本 `0.1.9+7`。依赖 `04` 的已确认媒体候选和 `01` 的任务/错误契约。

目标是建立独立于标签页的媒体下载、缓存和后台恢复。非目标是与软件更新共享缓存或状态、任意 URL 下载、把媒体缓存放进业务备份、或在 Flutter 保留第二份可写任务状态。

## 模块与状态

- 原生使用 Media3 DownloadManager/DownloadService 或固定等价组件；原生任务仓库是唯一写权威。
- `MediaTask` 只传递任务快照和事件；缓存键包含候选身份、清晰度、音轨和必要响应特征。
- 状态：`排队 → 下载中 ↔ 暂停 → 完成/可播放`，异常为 `取消/失败/重新授权`。
- 缓存私有目录不进入备份；播放、导出和投屏通过引用计数/占用令牌防止删除。

## 执行步骤

1. 定义缓存键、任务 ID、候选/授权引用、磁盘配额和错误码。
2. 实现开始、暂停、继续、取消、删除、离线播放和边下边播。
3. 复用更新系统已验证的 Range、If-Range、分片、侧车、重试和通知思想，但采用独立协议。
4. 处理进程死亡、前台服务停止、网络切换、磁盘不足、无效 Range、404 和签名过期。
5. 进程恢复后核对任务仓库、Media3 状态和缓存文件，不能盲目从零下载。
6. 需要旧 Cookie/凭据时进入“重新授权”，不得静默读取。
7. 向 `06` 输出完整 HLS 缓存/分片映射，向 `07` 输出可投屏缓存资源。

## 删除、恢复和回滚

- 取消停止任务但保留缓存；删除只允许在无活动播放/导出/投屏引用时执行。
- 任务仓库不可用时只读显示缓存状态，暂停新写入并保留文件。
- 校验失败删除不完整分片并回到可重试状态，不删除其他任务缓存。
- 网络和系统终止恢复时优先续传；状态不一致则重建任务快照并记录原因。

## 计划测试与验收（本轮不执行）

- 后台下载、暂停/继续、断网恢复、进程死亡恢复和通知可见性。
- 完整缓存离线播放、边下边播、未缓存拖动和缓存复用。
- 删除被播放/导出/投屏引用阻止，引用释放后可删除。
- 凭据过期、网络切换、磁盘不足、Range 异常和错误码。

输出：独立下载任务/缓存 schema、恢复 runbook、占用引用契约和 HLS 输入。禁止在本阶段实现 FFmpeg 转封装或 DLNA 控制。
