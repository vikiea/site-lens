# 下载错误可读化

## 问题和目标

下载失败目前把 `Connection closed while receiving data`、完整 URL 和内部错误细节直接暴露给用户，既难以理解也可能包含敏感查询参数。需要提供“查看错误原因”的人类可读详情，同时保留脱敏后的诊断上下文。

## 实现设计

- 错误分类覆盖网络中断、超时、HTTP 状态、权限/重新授权、存储不足、格式不支持和 Range 不可用。
- 列表只显示短状态；详情面板显示简短原因、可执行建议、失败阶段、已下载大小和是否可重试。
- URL 只显示 origin/path 摘要，删除 query、Authorization、Cookie、token 和签名参数。
- 统一 `friendlyError` 与下载错误码映射；底层异常类名、堆栈和原始响应不进入用户界面。
- 失败状态保留可供日志分析的结构化错误字段，但结构化字段同样先脱敏。

## 验收

- 截图中的连接错误显示为“网络连接中断，请重试”，不出现完整媒体 URL。
- 用户可在“查看详情”中知道失败阶段和下一步操作。
- 重试、重新授权和删除任务的动作与错误分类一致。
- 增加错误映射、URL 脱敏和详情 Widget 测试。

## 独立审查门禁

审查日志/界面两条错误路径、敏感参数脱敏和错误码兼容；提交前通过媒体服务、网络和 Widget 测试。
