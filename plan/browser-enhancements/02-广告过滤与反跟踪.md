# 02 广告过滤与反跟踪

## 基线、目标与依赖

基线为 `origin/main@ca904c36ff6bede07ab8092dde16e9903a41a7c8`，应用版本 `0.1.9+7`。依赖 `01-基础契约与数据迁移.md` 的 `FilterSnapshot`、`FilterPolicy` 和 `HostFilterContext`。

目标是在现有 WebView、检测隔离和脚本安全边界内加入请求过滤、页面过滤和可解释诊断。非目标是任意代理、响应正文重写、CSP 改写、Cookie 读取或实时等待 Dart/网络的拦截器。

## 模块与策略

- 过滤引擎采用固定版本/提交，并记录源码、许可证、构建参数和摘要；依赖不可构建时停止，不静默替换。
- 规则源状态保存于 Drift，规则正文和编译产物保存于私有目录；`FilterSnapshot` 是宿主读取的不可变版本。
- 策略优先级：全局默认 → Profile 设置 → 已知域名例外。域名例外不能由一次跨域重定向自动扩展。
- 发现/验证宿主使用同一快照，但不加载用户脚本、不共享浏览 Cookie。

## 数据流和状态机

```text
源下载 -> 大小/文本校验 -> 编译 -> 快照校验 -> 原子发布
                                     \-> 失败：保留上一有效快照
请求 -> HostFilterContext -> 请求规则 -> 放行/阻止/诊断计数
DOM -> CSS/安全 scriptlet -> 页面过滤 -> 脱敏诊断
```

快照状态：`缺失 → 下载中 → 编译中 → 有效`，异常为 `损坏/失败/降级`。当前页面继续使用绑定的快照，规则更新提示“下次加载生效”，不得自动打断播放。

## 执行步骤

1. 固定引擎和规则源版本，记录许可证、大小上限、下载超时和摘要算法。
2. 实现规则源下载、原子写入、编译、摘要、回退和手动刷新状态。
3. 把 `FilterPolicy` 解析为全局/Profile/域名三层继承结果，并保留实际来源。
4. 在原生请求拦截点使用已准备快照；禁止在回调中等待磁盘、Dart 或网络。
5. 为页面层加入 CSS、动态 DOM 观察和已审计 scriptlet，明确 document-start 能力不足时的降级范围。
6. 加入当前文档诊断面板：快照摘要、阻止计数、未支持规则、降级原因和脱敏 URL。
7. 为检测宿主接入同一快照，确保不加载用户脚本和浏览凭据。

## 失败、回滚和安全边界

- 下载、编译、摘要或原子发布失败时继续用上一有效快照。
- 快照损坏或引擎能力缺失时只启用已证明安全的请求过滤，显示降级状态。
- 未知规则语义不猜测为放行或阻止；记录未支持规则并遵循固定默认策略。
- 规则诊断必须脱敏查询参数、Cookie、Authorization 和敏感路径。

## 计划测试与验收（本轮不执行）

- 固定规则源摘要、大小限制、原子发布、损坏回退和断网恢复。
- 广告/反跟踪请求不会到达可控测试服务器；例外只影响目标 Profile/域名。
- CSS、动态 DOM、已审计 scriptlet 和未支持规则降级。
- 浏览与检测使用同一快照版本，脚本 GM 网络不被过滤状态绕过。
- Android WebView 能力缺失时有明确降级，不把低等级结果当设备验收。

输出：过滤引擎构建记录、规则源/快照 schema、策略解析器、诊断字段和给 `03`/`04` 的边界契约。禁止在本阶段实现脚本授权、媒体下载、FFmpeg 或 DLNA。
