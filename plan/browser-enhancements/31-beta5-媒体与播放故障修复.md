# beta5 媒体与播放故障修复

基线：9b83644 / v0.3.0.beta4。用户授权：修复八项问题，每次提交前独立审查；如 emulator-5554 可用则受控验证，通过可执行检查后发布测试包；真实设备验收单独记录。

## 子计划与完成条件

1. 导出与媒体缓存：隔离 isolate 输入；验证导出目标 URI；删除导出默认保留任务缓存，显式选项才联动清理；检测历史缺失缓存并提供重下入口。
2. 播放名称与格式：追踪标题/集数来源、冻结身份，避免同名错集；消除 unsupported_format 的无上下文错误，实际不支持格式需给出可读原因。
3. 手势公共菜单：直接菜单交互，按最长选项宽度，清除 focus/pressed 灰底并保留语义/键盘操作；同步 UI Skill 和组件测试。
4. WebView：调查点击播放退出路径，修复可证明的生命周期问题；补采集原生进程退出证据，不能把日志增强称为真实崩溃已复现。
5. DLNA：核对服务 URL/协议/元数据/中继；设备确认有效播放后才提示成功，失败释放会话。
6. 验证与发布：针对性回归、make check、Kotlin 编译；独立审查通过后提交；可用模拟器执行受控检查；GitHub 测试发布与人工验证报告同步，记录缺失证据。

## 当前证据

- 工作区与远端分支一致，起始状态干净。
- adb devices -l 无设备；稍后在验证阶段再次执行一次有界检查。
- 导出 isolate 仅发送路径字符串；SAF tree/文档目标分别交付、完整回读。
- 删除导出默认保留缓存；历史共享 MP4 先复制至任务缓存；原生/文件/任务删除共用排他锁。
- 历史集数只对同资源身份且缺值回填，显式集数覆盖旧页面标题，无法推断的同名内容给来源区分。
- HLS 检查清单、所有分片/密钥/初始化段非空；损坏任务可重下。
- 公共菜单与 UI Skill 完成；280dp、2.5倍字号回归通过。
- DLNA 使用真实服务端点/版本与 Sink、目标路由地址、DLNA HTTP/DIDL 元数据；PLAYING+当前媒体确认后才成功；HLS实际拒绝单次MP4回退。
- WebView主/临时probe均处理renderer退出；dead cleanup不访问失效provider，释放OS媒体owner及probe/profile；原生退出日志改成入库后ack与重放去重。
