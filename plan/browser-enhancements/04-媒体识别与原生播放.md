# 04 媒体识别与原生播放

## 基线、目标与依赖

基线为 `origin/main@ca904c36ff6bede07ab8092dde16e9903a41a7c8`，应用版本 `0.1.9+7`。依赖 `01` 的 `MediaCandidate`/`MediaTask`、`02` 的过滤结果和 `03` 的 `registerMedia` 授权。

目标是在保留网页播放器、`BrowserMediaController`/`BrowserMediaService` 网页媒体生命周期和后台播放策略的前提下，加入用户主动选择的候选和 Android 原生播放。非目标是自动替换网页播放、后台静默播放、DRM 破解和 iOS 原生交付。

## 候选来源与安全边界

- 页面 `video`/`audio` 元素和安全可观察状态。
- 经 `SiteLens.registerMedia` 登记的候选。
- 候选必须包含 `hostId`、`generation`、来源文档、URL、标题、MIME/格式提示和来源类型。
- `blob:`、失效 URL、跨 generation、销毁标签和被过滤阻止的资源不得自动变为可播放候选。
- URL 去重保留必要签名参数，不能合并不同资源。

## 原生播放状态机

```text
准备中 -> 播放 <-> 暂停
       -> 缓冲 -> 播放
       -> 完成 / 失败 / 已停止
```

使用 Media3 或固定等价组件；同一时刻一个原生会话。关闭来源标签不停止已启动会话，但进程重启不自动恢复带凭据播放。需要 Cookie/Referer/登录态时必须针对本次任务重新确认，重定向不能复制敏感头。

`BrowserMediaController` 继续只负责网页媒体；原生会话拥有独立任务 ID、状态和错误码，不复用网页 host 的暂停/恢复逻辑。

## 执行步骤

1. 在 Pigeon/原生层接入候选快照、可用动作和 fail-closed 校验。
2. 从 DOM/媒体事件收集候选，过滤无效 URL、旧 generation 和受阻资源。
3. 实现原生会话创建、替换、播放/暂停、拖动、倍速、全屏、停止和错误回传。
4. 建立用户主动触发的浏览菜单/候选面板，复用现有 Site Lens 玻璃 UI。
5. 明确网络凭据重新授权、重定向和停止后的资源释放。
6. 为 iOS 返回明确不支持，不在文案中声称跨平台完成。

## 失败处理与验收（本轮不执行）

- 过期 URL、格式不支持、凭据失效、重定向越界和 host 销毁都返回可区分错误。
- 新播放替换旧播放前先停止并确认旧会话释放；失败时保留旧会话状态或明确停止。
- 覆盖直接 MP4、HLS、Referer、登录态、过期地址、标签关闭和进程重启。
- Android 真实设备验证播放、暂停、拖动、倍速、全屏和停止；模拟器结果不得替代设备门禁。

输出：候选模型、原生会话状态机、授权输入和供 `05`/`06`/`07` 使用的资源引用。禁止在本阶段实现下载、导出或投屏。
