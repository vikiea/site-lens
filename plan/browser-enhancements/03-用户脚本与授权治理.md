# 03 用户脚本与授权治理

## 基线、目标与依赖

基线为 `origin/main@ca904c36ff6bede07ab8092dde16e9903a41a7c8`，应用版本 `0.1.9+7`。依赖 `01` 的 generation/DTO 契约和 `02` 的过滤、网络边界。

当前 `ScriptService`、metadata 解析、`@match`/`@exclude`、隔离世界、GM 存储/网络/菜单、固定依赖与资源摘要、`approved_digest`、全局关闭和 generation 校验均视为已有能力。本计划不重写这些边界。

## 目标、非目标和接口

目标是增加 declared/public 联网模式、统一批准失效和 `SiteLens.registerMedia` 候选登记。非目标是脚本市场、静默更新、Cookie/Authorization 读取、任意原生文件访问、脚本直接启动播放/下载/投屏。

批准摘要新增：格式版本、联网模式、源码摘要、依赖/资源摘要、授权时间和原因。`declared` 遵守 `@connect`；`public` 只放宽到公网目标，必须逐脚本显式确认，不能从档案包或备份继承。

## 生命周期状态机

```text
编辑/依赖变化 -> 重新计算摘要 -> 撤销旧批准 -> 用户确认 -> 激活
导航/关闭/销毁 -> 取消 GM 请求 -> 清理菜单/租约 -> 旧 generation 失效
```

所有保存、编辑、启用、禁用、全局关闭和授权变化走统一控制器：取消旧请求、撤销文档注册和菜单、重配宿主、重载受影响标签、重新读取状态。重载失败必须显示未完成，不能报告为已清理。

## `registerMedia` 约束

- 只登记候选，候选必须绑定 `hostId`、`generation`、来源 URL、媒体 URL、标题和格式提示。
- 不允许传入 Cookie、Authorization、Web Storage、原生路径或任意 capability token。
- 不允许脚本直接开始下载、播放、导出或投屏。
- 旧 generation、销毁标签、失效 URL 和 `blob:` 候选不得继续使用。

## 执行步骤

1. 扩展批准存储与摘要计算，保留旧批准的兼容读取和 fail-closed 行为。
2. 加入 declared/public 选择、逐脚本确认和审计原因；模式或源码/依赖/资源变化立即撤销批准。
3. 统一编辑、启停、全局关闭、导航和标签销毁的请求取消、菜单清理和重载流程。
4. 在网页运行时和原生桥增加 `registerMedia` grant，复用 `MediaCandidate` 校验。
5. 设计预置脚本稳定 ID、用户副本和升级不覆盖规则；新导入默认关闭。
6. 把过滤策略和 GM 网络权限串接，确保脚本无法绕开 `02` 的私网/TLS/大小限制。

## 失败、回滚和计划验收（本轮不执行）

- 新批准格式无法解析时保持脚本关闭，旧格式仅按已验证兼容规则读取。
- public 确认缺失、摘要不匹配、主框架/来源/generation 不符时拒绝执行。
- 旧 GM 请求迟到时只记录取消，响应仍必须经过原有身份校验。
- 回归覆盖已批准脚本、模式切换、依赖/资源变化、SPA/重定向、历史恢复、禁用重载和菜单清理。
- `registerMedia` 只能创建受 generation 约束的候选，不能带敏感凭据。

输出：批准格式、授权状态机、统一启停流程、媒体登记契约和审计字段。禁止在本阶段实现原生播放器、下载、FFmpeg 或 DLNA。
