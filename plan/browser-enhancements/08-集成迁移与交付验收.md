# 08 集成迁移与交付验收

## 基线、目标与依赖

基线为 `origin/main@ca904c36ff6bede07ab8092dde16e9903a41a7c8`，应用版本 `0.1.9+7`。本计划依赖 `01`-`07` 的契约、迁移、过滤、脚本、媒体、下载、导出和投屏输出，必须最后执行。

目标是定义跨模块回归、迁移、设备/发布门禁和交付证据。非目标是以计划文档代替实现、测试、真实设备验收或正式发布。

## 跨模块场景

1. 更新规则源；当前页面继续播放；刷新后绑定新快照。
2. Profile 继承和域名例外生效；无关域名不继承。
3. 禁用脚本后 GM 请求取消、标签重载、菜单清理；public 授权不从备份继承。
4. 过滤和检测使用同一快照；脚本不能绕过网络边界。
5. 用户授权媒体后关闭标签，原生播放/下载继续；旧 generation 候选被拒绝。
6. 下载中播放，完成后导出 MP4；被播放/导出/投屏占用的缓存不可删除。
7. 凭据过期、网络切换、磁盘不足、设备离线进入明确的暂停/失败/重新授权状态。
8. 备份恢复保留过滤配置，脚本重新确认，媒体缓存、凭据和投屏会话不恢复。

## 验证分级与依赖门禁

- **L0**：文档、纯模型、规则解析、局部工具检查。
- **L1**：Dart、数据库、设置和服务层变更，运行 `make check`。
- **L2**：WebView、Pigeon、脚本运行、过滤桥接、原生宿主和媒体桥接，运行保护集成流程。
- **L3**：Android 生命周期、后台媒体、下载恢复、系统媒体按钮、恢复和真实端到端，运行 `make acceptance DEVICE=...`。
- **L4**：正式 APK、签名、包名、发布工作流和版本行为，运行 `make build-release` 及必要的 L3。

没有设备时可以完成低等级验证，但缺失的 L2/L3/L4 证据必须标记为待验收。每个阶段的前置计划、迁移结果、回滚演练和独立审查均通过后才能进入下一阶段。

## 交付证据清单

- Git revision、分支、工作区状态和未提交文件说明。
- Flutter/Dart/Android SDK/WebView 版本。
- 第三方组件版本、提交、许可证和构建参数。
- 数据库迁移、ProfilePack 兼容、备份恢复和敏感字段排除证据。
- 过滤源/快照摘要、回退结果、候选/任务恢复、缓存复用和错误状态。
- 导出文件实际播放检查；DLNA 设备型号、固件和接收端播放结果。
- 内存、磁盘、后台服务、请求耗时和未完成设备/平台项目。

## 执行步骤、回滚和验收（本轮不执行）

1. 固定每阶段输入 revision 和证据目录，运行对应最低门禁。
2. 按 DAG 顺序执行跨模块场景，失败时先恢复上一兼容版本/快照/任务状态，再分析根因。
3. 在提交前完成独立审查，确认文档中的“已通过”均有终端证据。
4. 正式包单独构建、校验 application ID/签名、安装烟测并记录发布资产；未满足条件不得发布。

本轮只生成计划文档，因此上述测试、构建、安装、发布和设备验收全部保持未执行状态。

输出：跨模块回归矩阵、L0-L4 门禁表、证据模板、回滚顺序和正式交付清单。
