## 2. 目标与非目标

目标是把广告过滤、脚本授权治理、媒体识别、下载、HLS 导出和 DLNA 投屏拆成可独立审查的增量计划，并建立跨模块数据边界、回滚边界和验收证据要求。

非目标包括完整浏览器扩展兼容、指纹伪装、DRM 破解、直播录制、实时转码、脚本市场、任意 URL 代理，以及把计划内容误报为已实现功能。

## 4. 不变架构约束

1. `AppSettings` 只保存用户偏好；过滤源、过滤策略和规则快照元数据进入 Drift，规则正文和编译产物进入应用私有目录。
2. Cookie、Web Storage、Authorization、GM values、运行时句柄、媒体凭据和投屏令牌不进入业务备份、数据库或 Pigeon DTO。
3. 跨层对象至少携带 `hostId`、`generation`、来源 URL、候选/任务 ID；导航、标签关闭、WebView 销毁和进程重启必须使旧对象失效。
4. 继续使用 `pigeons/web_host.dart`，新增 DTO 不暴露 Media3、FFmpeg 或 DLNA SDK 类型；生成的 Dart/Kotlin/Swift 绑定必须同步审查。
5. 网页播放器仍是默认路径；原生播放、下载、导出和投屏只能由用户主动触发。
6. Android 是本轮交付重点；iOS 只保留明确的不支持结果，不把 Android 能力宣称为 iOS 已交付。

## 5. 阶段和严格依赖

```text
M0 基线与证据
  -> M1 基础契约与数据迁移
  -> M2 广告过滤与反跟踪
  -> M3 用户脚本与授权治理
  -> M4 媒体识别与原生播放
  -> M5 下载、缓存与后台任务
  -> M6 HLS 转封装与 MP4 导出
  -> M7 DLNA 与媒体中继
  -> M8 集成迁移与交付验收
```

- `01` 输出统一身份、DTO、迁移、备份和错误契约，`02` 至 `07` 必须依赖它。
- `02` 先于 `03`，因为 GM 网络权限不能绕过过滤和网络安全策略。
- `03` 先于 `04`，因为媒体候选登记是脚本显式授权能力。
- `04` 先于 `05`，因为下载任务必须引用已确认候选。
- `05` 先于 `06`，因为导出只读取已定义的本地缓存和分片映射。
- `06` 先于 `07`，因为投屏优先复用导出的 MP4 和统一媒体授权。
- `08` 最后编写，汇总迁移、回滚、验证、正式包和交付证据。

当前 beta 反馈闭环另行拆分为 `09`-`16`，不改变 `01`-`08` 的基础契约：

```text
09 媒体大小与任务展示

11 媒体标题/集数一致性
12 媒体管理设置入口

14 媒体下载提示时长
```

其中 `09`、`11` 先于 `10` 的任务页展示重构；`13` 是共享 UI 基础变更，完成后再改业务页面；`15` 先于 `16`，日志只能收集脱敏后的错误摘要；全部子计划完成后统一执行 `08` 的 L0-L4 发布门禁。

## 7. 计划执行规则

每个阶段先做最小闭环，再补 UI 和异常路径；每阶段完成后独立审查，未满足前置条件不得进入下一阶段。失败时保留旧快照、旧数据库或旧任务状态，优先回滚到上一兼容版本。缺少真实设备、WebView、接收端或签名证据时只能标记为待验收，不能标记为通过。
