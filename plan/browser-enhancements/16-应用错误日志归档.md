# 应用错误日志归档

## 问题和目标

APP 相关异常目前分散在 SnackBar、状态字段和原生日志中，无法统一回看。需要增加本地错误归档能力，帮助定位 WebView、媒体、下载和设置问题，同时不保存账号凭据、Cookie、完整签名 URL 或脚本正文。

## 实现设计

- 建立结构化 `AppErrorEvent`：时间、模块、级别、可读摘要、错误分类、脱敏上下文、版本、平台和关联任务/标签 ID。
- 统一捕获 Flutter framework/isolate、`runZonedGuarded`、关键异步边界、WebView renderer、媒体桥接和下载回调错误。
- 归档写入 Drift，限制条数/总大小，按时间淘汰；写入失败不能反过来导致 UI 崩溃。
- 设置 → 关于/媒体管理提供“错误日志”查看、复制脱敏摘要和导出文本；导出前再次脱敏。
- 所有 URL 只保留 origin/path，删除 query/fragment；不写入 token、Cookie、Authorization、脚本源、媒体完整签名地址和本地绝对路径。
- 日志级别默认 warning/error，提供用户主动开启详细诊断的短期开关，关闭后自动恢复默认。

## 验收

- WebView 崩溃、下载失败、媒体播放失败和设置异常都能在日志页找到对应摘要。
- 日志页自身在数据库损坏、写入失败或大量错误时仍可打开。
- 导出内容不含 token、query 签名、Cookie、脚本正文和异常堆栈中的敏感值。
- 冷启动、后台恢复、应用升级和数据库迁移后日志可读且有容量上限。

## 独立审查门禁

审查全局捕获覆盖、递归错误保护、隐私脱敏、迁移/淘汰和导出；提交前通过数据库、错误映射、Widget、Android 生命周期和日志导出测试，再进入 `08` 的发布验收。
