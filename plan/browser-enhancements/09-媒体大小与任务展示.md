# 媒体大小与任务展示

## 问题和目标

媒体任务页当前把任务进度中的数值直接交给显示层，截图中出现 `116 GB`、`170 GB` 等明显不符合实际媒体大小的结果。需要确认单位来源、避免字节/KB/MB 重复换算，并让列表、详情、下载器状态使用同一格式化入口。

## 根因调查

1. 对照 `MediaTask.bytesDownloaded`、`totalBytes`、Android `DownloadManager` 的列值和 Dart HLS 下载累计值，确认每个边界的单位都是 bytes。
2. 检查数据库恢复和 Pigeon/MethodChannel 解码，禁止把已格式化字符串或 KB 数再写回整数大小。
3. 对 `-1`、`0`、未知总大小、超过 TB、整数溢出和重试后累计值建立测试样本。

## 实现边界

- 以 bytes 作为唯一持久化单位；格式化只发生在 UI/日志摘要层。
- 统一 `B / KB / MB / GB / TB` 的 1024 进制格式化函数，保留有限小数并按语言习惯显示。
- 进度条分子、分母和文字来自同一个任务快照，不能把百分比当作字节。
- 详情页显示原始可审计数值和人类可读值时，原始值不得暴露实现错误或内部状态。

## 验收

- 1,048,576 bytes 显示为 `1 MB`；未知总大小不显示错误的总量。
- Android、普通 HTTP、HLS 和恢复任务显示一致。
- 重试不会把已下载大小乘以 1024 或重复累加。
- 增加格式化、数据库恢复和原生状态映射测试。

## 独立审查门禁

提交前审查单位边界、溢出和恢复路径；至少通过 `flutter analyze`、媒体服务测试和 `./tool/check.sh` 的 L1/L2 相关阶段。
