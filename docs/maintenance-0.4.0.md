## 执行顺序

F/B 已交付的行为先复核，随后 C1 → C2 → D → E。D 的在途文件保持独立，不能混入其他批次提交。高噪声的独立调查可委派只读子代理，主代理负责单写者集成、验收和发布。

## 5554 与资源

使用项目 emulator-check 和带数据库备份/恢复的 acceptance runner。首选 sl_g37、2 核、请求 3072 MiB（允许系统最低 4096 MiB）、host GPU、冷启动。构建与模拟器尽量分阶段运行；只停止本任务已确认空闲的构建 daemon，不终止其他项目或应用。

每 30–60 秒采样 ADB、boot、前台活动、测试进展、进程与宿主内存，并记录 Swap 作为诊断信息。遇到 ADB 丢失、重复 shell 超时、测试进程无进展且空闲、高内存压力、可用内存持续低于约 20%、runner 超时或清理/恢复失败时保存日志并停止该次设备验证；Swap 剩余量不再单独触发停止。API 34 以下、API 34+ Vulkan 与非 Vulkan、真实设备的差异分别保留验收边界。

验收包可以在启动模拟器前顺序构建，再退出本任务的构建进程。预构建产品包与测试包必须有受控构建证明，校验产品入口、实际 suite、角色、SHA-256 和源码指纹；不能仅凭相同包名把旧 APK 当作当前验收证据。短套件与完整 L3 分开报告，恢复时必须安装产品入口。

## E 子计划：后台播放与系统控制

此项尚未实施，不能把现有网页通知服务视为原生播放器已经支持后台播放。

1. 由 `NativePlaybackService : MediaSessionService` 持有原生 ExoPlayer、MediaSession 和队列；Activity 只持有控制器连接与 Texture/Surface。分开解除显示绑定和显式停止，重连先读取当前会话，避免重复打开媒体。
2. 授权后一次提交稳定条目身份、来源与标题的队列快照。Flutter、通知和锁屏共用原生切集接口；分别暴露上一集、下一集能力，首尾不能发布无效按钮。保留逐条 HTTP 来源和本地 HLS 构造行为。
3. 文件 lease 随后台会话存活；页面销毁或 Engine 重建不能解除仍在播放文件的删除保护。稳定队列身份和播放状态必须可重连，进程死亡后的自动恢复另行界定。
4. 保留 ExoPlayer 音频焦点、noisy 处理，并验证灭屏持续播放。增加原生/网页的所有权仲裁，原生接管先暂停网页并撤销其通知；迟到回调不能重新抢占。
5. 网页仅在明确页面 MediaSession handler 或安全媒体元素路径可用时发布动作；blob/MSE 不猜测上下集。诊断只读展示 owner、Service/控制器/Surface、队列边界、逐动作能力、实际播放观测和命令结果，未知不能写成不支持。
6. 依次验证 Activity 重建与画面重连、Home/锁屏控制、上下集边界和标题同步、焦点抢占与耳机拔出、后台删除保护、网页不支持动作与失败 ACK。至少 L3；Manifest、依赖及正式构建按自动分级补足 L4。
