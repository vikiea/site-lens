## 1. 设备准备

要求：

- Android 设备，优先 API 34 以上；记录型号、Android 版本、API level、ABI、WebView provider。
- 设备至少有 2 GB 可用空间；测试期间只连接一个 ADB serial。
- 允许通知权限；关闭会遮挡播放器或通知的浮窗。
- 后台测试允许应用通知、媒体播放和电池策略所需权限；记录是否启用省电限制。
- DLNA 项目需要手机和电视/盒子在同一局域网；记录 receiver 型号、IP、固件和 MIME 能力。

```sh
make devices
adb -s <DEVICE_SERIAL> get-state
adb -s <DEVICE_SERIAL> shell getprop ro.build.version.sdk
adb -s <DEVICE_SERIAL> shell getprop ro.product.model
adb -s <DEVICE_SERIAL> shell dumpsys webviewupdate
adb -s <DEVICE_SERIAL> shell getprop ro.product.cpu.abi
adb -s <DEVICE_SERIAL> shell df -h /data /sdcard
adb -s <DEVICE_SERIAL> shell dumpsys battery
```

无线 ADB 只在测试开始前连接一次，记录完整 serial；中途断开后停止该批次并重新预检，不自动换端点。

推荐使用验收 runner：

```sh

  --skip-build --skip-check --no-adb-recovery \
```

如果 runner 产生 `backup retained at ...`，保留该目录。失败或恢复异常时不要覆盖原备份。

## 4. 观看保存

使用一个用户已经授权、可以稳定识别剧目和集数的测试页面：

1. 打开页面并确认当前选中 tab 正在播放第 1 集。
2. 等待一次有效播放证据后打开媒体管理，确认创建一条观看保存记录。
3. 暂停，等待状态上报；确认位置增加、状态为暂停、时长不回退。
4. 恢复后再次暂停；确认仍是同一 owner，旧事件不能覆盖新进度。
5. 切换到另一 tab 播放第 2 集；确认新增 owner，且第 1 集不被覆盖。
6. 离开页面、关闭 tab、重新打开媒体管理；记录仍存在，不自动创建下载任务。
7. 删除观看记录；确认共享资源、媒体任务、MP4 artifact 不被误删。
8. 只出现候选但未播放、推荐元素播放、无集数或集数冲突的资源不能自动创建记录。

记录：页面 URL 的脱敏标识、tab、剧目/集数、owner 数量、任务数量、进度前后值、日志时间点。不要保存 cookie、Authorization 或私有媒体 URL。

## 5. 共享媒体缓存和边下边播

1. 从同一资源分别创建观看保存、手动下载和原生播放请求；确认资源身份相同、writer 只有一个。
2. 观察首个 HLS 分片提交后启动原生播放；确认下载尚未完成时已经可播。
3. seek 到未缓存位置；确认播放器等待有限时间，目标分片优先请求，超时后任务仍可恢复。
4. 切换网络到受限/计费网络；确认自动补齐暂停并显示原因，已提交分片仍可读取。
5. 取消一个 owner；确认其他 owner 的传输继续，资源文件仍存在。
6. 停止所有 reader 和 writer 后删除最后一个 owner；确认共享资源才被回收。
7. 杀掉应用或让系统回收后重新打开；确认已提交前缀、任务状态和授权状态可恢复，未提交 `.part` 不被当作完整文件。

检查点：任务并发不超过 4；当前播放/seek 优先；普通任务最终获得执行机会；空间不足和系统限制不能静默删除文件。

## 6. 原生后台播放和系统控制

1. 从完整本地 HLS/MP4 启动原生播放，确认通知、播放/暂停、seek 和倍速状态。
2. 按 Home 退后台，确认音频继续且通知仍由应用的 MediaSession 提供。
3. 锁屏后使用锁屏控制播放/暂停/seek；记录通知动作和播放器状态。
4. 从应用页面 detach 播放 surface，再重新打开页面；确认仍是同一 session，不重复创建播放器。
5. 从通知暂停后回到应用；确认用户暂停意图保持，buffering 不会把状态改成用户播放。
6. 拔出耳机或触发音频焦点丢失；确认暂停原因可见，恢复动作符合系统策略。
7. 显式停止；确认通知清理、session 关闭、读 lease 释放，随后文件删除/移动可以执行。
8. 从最近任务移除、强制停止应用、系统回收进程后重新打开；确认不会未经用户操作自动播放，显示可恢复、已暂停或需重新授权状态。

每次都记录 `adb shell dumpsys media_session`、通知状态、播放器 UI 状态和应用日志。页面重绑通过不等于进程杀死恢复通过，必须分别记证。

## 7. HLS、MP4 和媒体所有权

1. 对完整 VOD HLS 记录 m3u8、MAP/init、音视频分片、key/Range 元数据的长度和摘要。
2. 未完整或缺片时尝试导出，必须拒绝且保留源缓存和断点。
3. 完整后导出 MP4；确认使用本地缓存，不发生远程回源或隐式编码。
4. 播放 MP4 并执行暂停、seek、恢复和 EOS；确认样本/时间轴校验通过。
5. 删除下载任务；确认独立 MP4 文件和媒体库索引仍存在。
6. 删除 MP4 artifact；确认源 HLS 仅在仍无 owner/lease 时回收。
7. 破坏或移除索引后执行媒体库重扫；确认已发布 MP4 恢复为独立 catalog 身份。
8. 对 HLS 原始目录执行路径越界、缺片、远程 URI 和未授权 key 试验；必须拒绝。

当前 alpha11 的“本地 HLS”是共享缓存/播放/导出的受控输入；如果后续增加可移交 HLS 包导出，需要另加包内路径清单、授权材料策略和接收端兼容验收，不能把目录存在当作导出成功。

## 8. 后台授权刷新

1. 让已授权的 HLS 资源在后台传输中返回一次确定的 401/403。
2. 确认最多触发一次同源隐藏 WebView 刷新，页面不跳转到外站，不创建可见 tab，不执行用户脚本。
3. 确认 cookie/Authorization/Storage 不出原生到 Dart 或日志。
4. 刷新后校验剧目、集数、清晰度、音轨、manifest、分片序列、MAP/key 和内容身份；不匹配必须拒绝拼接。
5. 没有后台执行环境时显示 `waiting_execution`；实际刷新失败才显示 `reauthorize`。
6. 最终失败保留已有分片、任务进度和原 owner，等待人工重新授权；不能静默换候选。
7. 关闭后台补齐或蜂窝网络权限后，旧集刷新和下载均应暂停。

## 9. DLNA 后置验收

本机 relay 已有模拟器证据；真实电视/盒子必须单独验收：

1. 发现 receiver，记录设备描述、AVTransport endpoint 和 MIME 能力。
2. 使用完整本地 MP4 投屏，确认接收端实际出画、出声、标题正确。
3. 执行播放、暂停、seek、恢复、停止，并分别记录手机和 receiver 状态。
4. 停止后确认 relay 端口关闭、授权 token 失效、读 lease 释放，再验证本地删除。
5. SOAP 成功、HTTP 200 或设备声明支持 MIME 不足以判定真实播放通过。

## 10. 失败恢复和判定

失败恢复顺序：

1. 停止 runner，确认没有 Flutter/Gradle/ADB 子进程继续写设备。
2. 使用 runner 备份目录恢复原数据库、WAL/SHM 和产品包。
3. 核对来源设备摘要、文件清单、长度和 SHA-256。
4. 恢复失败则保留原始备份和完整日志，整批标记失败，不继续覆盖设备数据。

判定：

- `PASS`：当前 APK、当前 serial、适用项全部有直接运行证据，且恢复完成。
- `FAIL`：任一适用项失败、runner 非零、包身份不匹配、来源校验失败或恢复失败。
- `BLOCKED`：设备、授权站点或真实 receiver 缺失导致无法执行；已执行项仍保留真实结果。

禁止用模拟器结果替代真实设备结果，也禁止用原生契约测试替代后台、锁屏、通知、进程回收或真实 receiver 的行为证据。
