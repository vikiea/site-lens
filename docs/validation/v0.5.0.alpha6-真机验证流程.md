# Site Lens `v0.5.0.alpha6` 真机验证流程

本流程用于在 `emulator-5554` 通过后，对真实 Android 设备验收观看保存、共享 HLS 缓存、边下边播、原生后台播放、系统控制、HLS/MP4 导出、媒体所有权和后台授权刷新。

## 1. 包身份

- pubspec：`0.5.0-alpha6+104`
- 期望标签：`v0.5.0.alpha6`
- 包名：`dev.vikiea.site_lens`
- 验证命令：

```sh
python3 tool/verify_release_pubspec.py --tag v0.5.0.alpha6 --version-code 104
adb devices -l
```

记录设备型号、Android API、WebView 版本、ABI、网络类型、是否启用 VPN/代理和 APK SHA-256。真机通过不能替代模拟器自动化门禁；每个结论记录“通过 / 失败 / 未执行 / 不适用”和证据时间。

## 2. 安装和清理边界

```sh
adb -s <serial> install -r <apk>
adb -s <serial> shell pm clear dev.vikiea.site_lens
```

首次安装后授予通知权限；媒体测试前准备一个可访问的 H.264 TS 或 fMP4 HLS VOD，至少包含 3 个分片，并准备同一内容的 MP4 导出目标。不要使用 DRM、验证码、付费墙或登录绕过作为成功条件；这些场景必须记录为人工授权或 unsupported。

## 3. 观看保存

1. 打开测试站点并只播放当前选中的标签页。
2. 验证播放、暂停、切集、关闭页面后只保留一个观看 owner。
3. 验证列表显示集数、状态、进度和更新时间。
4. 删除观看记录，确认媒体任务、HLS 缓存和独立 MP4 仍存在。
5. 从另一标签页产生候选或旧页面迟到事件，确认不会更新当前集记录。

证据：屏幕录制或截图、观看保存列表、媒体任务列表和诊断日志中的 evidence/session identity。

## 4. 共享缓存和边下边播

1. 选择 HLS VOD，开始下载后在任务状态仍为“下载中”时打开“边下边播”。
2. 确认首帧早于全部分片完成，并且下载进度继续增长。
3. 删除或暂停下载任务前停止播放器，确认共享资源只在最后一个 owner 解除后回收。
4. 同一内容从两个任务启动下载，检查磁盘中只有一份共享分片，两个任务仍有独立索引。
5. seek 到已缓存区间，确认不重复下载；seek 到未缓存区间记录当前版本的等待或不支持原因。

当前 alpha6 交付的是已提交分片的增量清单和前台首播；未缓存远端 seek 的按需缺片调度仍需单独记录为待验收。

## 5. 原生后台播放和系统控制

1. 从本地完整 MP4 或 HLS 缓存启动“原生播放”。
2. 锁屏，使用锁屏媒体控件播放/暂停/seek；验证音频焦点和耳机拔出行为。
3. 按 Home 键退后台，确认播放继续，通知显示当前媒体和状态。
4. 从最近任务移除应用，确认媒体服务仍按系统策略运行；点击通知回到应用后 surface 能重新绑定。
5. 旋转屏幕或重新创建 Activity，确认 session、位置、倍速和播放/暂停意图保留。
6. 点击系统停止或应用停止，确认文件 lease 释放，随后删除/移动文件成功。

证据：`adb shell dumpsys media_session`、通知截图、锁屏操作结果、应用诊断日志和文件删除前后结果。若设备厂商限制后台播放，记录系统限制和“等待/不支持”原因，不将其记为媒体数据损坏。

## 6. HLS 导出和媒体所有权

1. 完整下载 HLS 后导出 MP4，验证输出可以播放、seek，且源 HLS 仍可播放。
2. 删除下载任务，确认独立 MP4 和媒体库索引保留。
3. 播放或投屏中尝试删除源缓存，确认操作被 lease 拒绝。
4. 停止播放/投屏后再删除，确认 owner 解绑、共享资源只在最后 owner 删除后回收。
5. SAF 交付目录权限撤销后重试，确认内部已校验 artifact 保留，错误可见。

## 7. 后台授权刷新

1. 使用需要 Cookie 的同一媒体任务制造一次 401/403。
2. 让 WorkManager 首次失败触发同源隐藏 WebView 刷新，确认通知无弹窗、无声音、无可见页面。
3. 确认刷新只访问任务原页面来源，跨站跳转、验证码、登录页或标题挑战进入人工重新授权。
4. 刷新成功后只重试同一任务、同一集、同一表示形式；不换候选、不自动播放、不清理断点。
5. 关闭后台刷新或系统不允许后台执行时，确认状态显示等待执行/人工重试，而不是伪报授权失败。
6. 验证刷新完成后 Cookie 明文不会出现在 Flutter 日志、通知、数据库或诊断详情中。
