## 修复范围与确定性回归

系统代理路径位于 `lib/network/transport.dart`。站点侦察和媒体请求会按当前路由建立连接；幂等请求在代理连接或超时失败时最多切换一次路由，证书错误、地址策略错误和取消不会误触发重试。`HttpProbe` 的单次路由等待为 4 秒，总预算为 10 秒。对应回归位于 `test/network_test.dart` 和 `test/proxy_redirect_test.dart`，代理 fixture 与编排由 `tool/android_proxy_fixture.py`、`tool/android_proxy_lease.py` 和 `tool/run_android_proxy_acceptance.py` 覆盖。

媒体来源与剧集归属由 `web_assets/media_lifecycle.js`、`lib/media/media_service.dart` 和 `lib/media/media_library.dart` 共同约束：显式剧集映射优先于旧 URL 标记；系列、来源路径、跨来源资源、页面 visit 和迟到响应保持隔离；无法确认的资源保持未知，不从候选数量或批次顺序推断集数。`tool/test_media_episode_identity.mjs` 的 39 项回归、媒体生命周期回归以及真机的 `MODERN_EXPLICIT_EPISODES_SPA_PASS`、`SAME_PAGE_MEDIA_AUTO_DISCOVERY_PASS`、`MEDIA_PAGE_RESTORATION_LATE_RESPONSES_PASS` 覆盖这些边界。

批次目录的显示名称由 `mediaFolderDisplayName` 清理批次后缀；物理目录迁移由 `lib/media/media_directory_migration.dart` 在冷启动执行，先校验复制内容，再提交 SQLite 路径重写，最后删除旧目录。媒体目录和 MP4 交付的本地回归验证了实际文件内容、路径重写、重复交付幂等和旧目录清理。当前验收没有把“应用内显示合并”当作真实文件系统合并证据。

关键结果：

- `proxyContract=true`、`acceptance=true`、`allFieldsRestored=true`；

## 模拟器验收与设备边界

模拟器配置：

```sh
make emulator-check EMULATOR_AVD=sl_g37 \
  EMULATOR_TIMEOUT=60 \
  EMULATOR_ARGS="--memory-mb 3072 --cores 2 --gpu host \
  --log build/android-acceptance/emulator-sl_g37-alpha19.log"
make acceptance DEVICE=emulator-5554
```

环境为 `sl_g37`、Android API 37、arm64、3 GiB、2 核、host GPU、WebView `145.0.7632.218`。完整 acceptance 结果为 **29 通过、7 失败**。

失败项：

- slash-less/redirecting entry URL 的 privileged script lease；
- same-document navigation 的 privileged lease；
- entry navigation redirect chain；
- 页面主动发起的 navigation lease；
- 新 landing tab 的 script menu；
- exported pack 导入后执行脚本；
- HEVC `media3_parity_test` 播放进度为 0，未达到 3800 ms。

模拟器诊断为 WebView `world=false`、`navigation=false`、`profile=true`、`codecs=64`、`hcppEngine=false`、`hcppState=unsupported`。因此脚本隔离、入口导航和 HEVC 失败属于模拟器能力边界；H.264 TS/fMP4、AES-128 TS/fMP4、Media3 路径安全、媒体库、MP4、DLNA、媒体控制、高质量 codec 列表和被动设备诊断均通过。模拟器证据不能替代指定真机的 WebView 155/HCPP/118 codec 证据。

## 后续真机复验顺序

```sh
make devices
make acceptance DEVICE=<IP:PORT>
python3 tool/run_android_proxy_acceptance.py <IP:PORT> \
  --output-dir build/android-acceptance/<case>
```

然后在设备诊断页记录 API、WebView、HCPP、renderer policy 和 codec inventory；在高质量模式下分别检查 Flutter 自有页面和 WebView 上方控件，并检查媒体批次目录的真实文件系统合并、MP4 目录名、当前剧集上下集隔离和跨系列隔离。设备断开时保留 acceptance 输出与 backup 路径，再使用项目的 restore 入口恢复数据。

## 尚未由本报告证明的范围

- API 34 以下、其他 GPU/Vulkan 后端和其他 WebView 版本；
- iOS、真实 SAF provider 的长期权限变化和真实 DLNA 接收端播放/seek；
- 真实站点的剧情、音轨和画面语义是否与页面集数文字完全一致；
- 物理 BFCache 常驻行为；当前生命周期用例中的页面恢复事件是受控测试事件；
- 长时间运行后的内存曲线、完整动画/连续滚动矩阵；
- AES-128 代理网络取 key、解密、播放和 remux；
- 观看保存、共享缓存和边下边播等仍在活动台账中标记为未完成的长期计划。

## 独立审查结论与发布边界

独立只读审查结论为 **CHANGES REQUIRED**，要求报告保留以下边界：

- 代理修复已有本地回归和当前真机专项证据，但专项证明的是受控代理契约，不覆盖所有真实 PAC、VPN 和站点出口；
- 媒体身份、迟到响应、跨系列隔离和批量播放列表已有本地与真机合成契约证据，但不证明真实站点剧情、音轨和画面语义；
- `lib/media/media_directory_migration.dart` 和 Android `NativeDownloadRuntime` 均有物理合并实现及本地回归，但本轮没有在真实 Android 下载根目录上制造旧批次目录并完成原生迁移验收；
- 当前真机 Media3 parity 已由 `build/android-acceptance/alpha19-media3-39517.log` 单独证明；
- HCPP/设备诊断已在 API 36/WebView 155 真机读取通过；Impeller 策略状态和 `quality=premium` 不等于 alpha15 的像素级视觉等价，仍需人工视觉复核。
