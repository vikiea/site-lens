# v0.3.0.beta16 人工验证报告

日期：2026-10-21（Asia/Shanghai）。基线为 `v0.3.0.beta15`。本轮修复 MP4 连续播放/音频、媒体索引恢复和缓存清理边界；取消模拟器和真机验收执行，保留现有设备用例并补充媒体扫描回归。以下“待人工验证”均不代表通过。

## 本轮改动与根因证据

- 用户提供的 227.059 秒 MP4 包含 H.264 B 帧视频和 AAC-LC 44.1kHz 双声道音轨。视频 MP4 样本时长出现大量 100 微秒/99.8 毫秒交替，音频 2055 个 MP4 包内实际包含 9778 个带 ADTS 头的 AAC 帧；并非没有音轨，也不是 SQLite 导致解码卡住。
- 导出改用 Media3 `Mp4Muxer` 保留视频解码顺序和 B 帧 PTS，由复用器生成 CTTS；逐个拆分 AAC ADTS 聚合包、剥离传输头，以 1024 个采样构建连续音频时钟。已用生产拆帧代码处理完整样本：2055 包恢复 9778 帧、227.045 秒；样本音频的传输时间戳与连续时钟最大偏差 31883 微秒；允许的抖动上限为 50000 微秒，超限明确失败，不丢弃音频帧。
- ASC、ADTS 与轨道的 profile、采样率、声道必须一致；检查全部分片轨道、关键帧、格式签名、音频覆盖、访问单元结束时间及 EXTINF 边界，写入 EOS，并重新读取输出核对轨道样本数。含 discontinuity 或无法保证兼容性的输入明确失败，不交付静默损坏 MP4。
- 原生播放器显式使用媒体音频属性、音频焦点及耳机拔出处理；WebView 前台通知服务更新失败时保留前台页面声音。
- `media_artifacts` 升级至 schema 11，与下载任务级联删除解耦；增加持久化 `source_key` 唯一性，并在迁移和恢复时优先保留任务关联索引。继续兼容 schema 8、9、10 的业务备份。
- 媒体页增加重新扫描，恢复应用 `media_exports` 和持久授权 SAF 目录下的 MP4 索引，保持原文件位置；扫描结果可在没有下载任务时展示、播放和管理。扫描、元数据回写、文件副本和删除共用索引队列及有效性检查，避免重复或幽灵索引。
- 有原 HLS 任务的媒体文件菜单增加“重新导出 MP4”。旧 MP4 不会被自动修复；从 HLS 重新导出后再验收，新 MP4 保存成功后清理旧副本，HLS 缓存继续独立保留。

候选去重、下载重试、DLNA 及此前功能沿用 beta15 基线；本轮不纳入工作区既有 `lib/domain/models.dart` 的嗅探去重改动。

## WebView 崩溃调查

用户取消设备验证前取得了 Android 16 上 2026-10-21 09:10:30（北京时间，对应日志 UTC 01:10:30）的记录：beta13 应用主线程 `pid=tid=15730` 在 `libwebviewchromium.so` 发生 SIGSEGV，fault `0x18`，系统报告空指针访问；WebView 为 `155.0.8059.43`，库 BuildId `e865a067f3eb12f45020bde21d3fd189cf9583a6`。尚未取得匹配符号，不能确认具体 Chromium 函数及触发操作。

本轮不将该崩溃归因为内存不足、玻璃策略或 DLNA，不宣称已修复。保留现有生命周期保护，后续以重现步骤、匹配符号及日志继续排查。
