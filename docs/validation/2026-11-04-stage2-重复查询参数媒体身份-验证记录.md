## 1. 缺陷

`mediaCandidateKey` 及同族身份函数在归一化 URL 时把同名 query 参数折叠成最后一个值，两个不同的内容选择被判定成同一个媒体：

- `?ep=1&ep=2` 与 `?ep=2` 同 key（真实资源不同，误合并）
- `?q=1&q=1` 与 `?q=1` 同 key
- `?q=1&q=2&q=3` 与 `?q=3` 同 key

基线**不**碰撞的是 `?q=1&q=2` vs `?q=1`（基线保留 `q=2`），首轮候选卡里这一条曾写错，已在 `stage2-candidates.md` 更正。

影响面：`lib/data/database.dart:1505` 按 id 覆盖候选行、`lib/media/media_service.dart:862` 合并下载任务身份。

## 2. 修复

`lib/domain/models.dart`：

- 抽出 `_volatileMediaQuery` / `_documentVolatileQuery` / `_authorizationVolatileQuery` 三组 volatile 参数集合，语义与基线一致（`token` 只在 document 与 authorization 两组里剔除）。
- 新增 `_mediaIdentityQuery(Uri, Set<String>)`：保留参数**按 first-seen 顺序、保留每一个重复值**。无重复时仍走 `url.replace(queryParameters:)` 保证单值 URL 字节不变；有重复时按 `key=value` 逐对 `Uri.encodeQueryComponent` 拼串，经 `Uri.replace(query:)` 写回。
- `mediaCandidateLocatorIdentity` 改为一次性构造：遍历 `queryParametersAll` → 过滤 volatile → 按 first-seen 顺序逐值拼 `key=value` → `Uri(scheme:, path:, query: retained.isEmpty ? null : retained.join('&'))`。中间不经过任何 Map，也不调用 `_mediaIdentityQuery`，因此 volatile 参数是否重复、写在哪个位置都不会渗进 locator；空 selector 回到 `https:/a.m3u8`（不留裸 `?`）。
- 删除已无引用的 `_retainedMediaParameters`。

已知遗留，本次**不修**：`mediaCandidateLocatorIdentity` 仍丢弃 CDN authority（基线既有行为，`test/media_service_test.dart` 的 `structured media identity survives a CDN authority change` 锁着这条语义）。四要素（现状 / 不修理由 / 影响面 / 重评条件）以 Reviewer 审查记录的写法为准。

## 3. 回归测试

`test/media_service_test.dart` 新增 3 个用例（+131 行）：

1. `repeated query parameters keep every value in media identity` — `?ep=1&ep=2` ≠ `?ep=2`、`?q=1&q=1` ≠ `?q=1`、`?q=1&q=2` ≠ `?q=1`。
2. `single-valued media identity keeps its exact byte form` — 单值 URL 的 key 往返不变；`token` 在 key / authorizationKey / documentIdentity 三处的 volatile 差异与基线一致。
