# 远程播放的准入门槛是站点凭证，不是设置开关

**Status**: accepted

## Context

ADR-0008 在凭证到位之前，用 `media_access/remoteSourceAllowed` 这个默认关闭的偏
好把远程来源关起来：判定对象只描述会话类型，服务与桥接层各自读同一个开关。它自
己写明了退休条件——「凭证票只需要把 `remoteSourceEnabled` 的判断从偏好换成凭证
检查」。

T4 把这条链补全了：应用侧单向推送凭证（ADR-0007），原生按站点凭证在每次请求时
注入令牌与 cookie，401/403 回传「凭证失效」，应用续期后重推，原生只重试一次。

## Decision

- **准入门槛换成站点凭证**：`NativeMediaSessionRoute.classify(raw, hasCredential)`
  只回答「这条地址如果放行属于哪一类会话」。凭证是否存在不再决定远程地址能否放
  行——**没有凭证的公开内容照常能播**，只是这一次请求不带注入头。
- **移除 `media_access/remoteSourceAllowed`**：判定对象、桥接层与服务都不再读这个
  偏好；`PREF_REMOTE_SOURCE_ALLOWED` 与 `preferenceAllowsRemoteSource` 被删除，
  `tool/test_native_media_contract.py` 从「必须存在」改成「必须不存在」。
- **凭证注入跟着地址走**：只有凭证声明服务于这条地址（同 scheme、同主机、同端
  口）时才注入；取不到就注入空集合。凭证只进请求，不进快照、日志、错误文案。
- **失效协议**（ADR-0007 Consequences 点名的那一份）：
  - 生产端是应用侧那一份，唯一真相；每次推送**整份覆盖**原生侧镜像，被拒绝的推
     送不覆盖（原生仍是上一份，下一次拒绝照样按凭证失效处置）。
  - 消费端只有 `push` / `clear` / `has` / `epoch` 四个方法；`has` 只回答有没有，
     没有任何通道把凭证值送回应用侧。
  - 原生读到过期副本时**不自行修补**：不清空、不刷写、不请求刷新（凭证刷新属于
     应用侧）。它把那份镜像当「没有凭证」，于是公开内容继续播，私有内容会以
     401/403 回传失效事件。
  - 应用收到失效事件后续期一次；成功则重推并让原生重试一次；失败或重推被拒都落到
    用户可见的「需要重新登录」，与网络失败、内容不可用的文案严格分开。
- **版本一致性**：记录版本号 `1` 在 Dart 与 Kotlin 两侧各写一次；版本不认识就整体
  不认识，按「没有凭证」处理。

## Rejected options

- **保留开关、凭证再加一层**：两道门里任何一道关着，用户看到的是同一句「远程媒体
  来源未开启」，而真正的失败原因（没登录 / 凭证过期）被藏起来。
- **把开关默认打开**：等于把判定对象变回通用 HTTP 客户端，只是换了个默认值。
- **没有凭证就拒绝远程地址**：会把公开内容一起挡掉，违背本票「公开内容不能因此被
  挡」的验收条件。

## Consequences

- ADR-0008 作废（Status: superseded by ADR-0009）；它描述的「远程播放是管道、不是
  能力」的阶段结束，远程播放对用户打开。
- 公开内容与私有内容走同一条会话路径，区别只在注入头；失败归因要靠 401/403 事件，
  不再能靠「开关没开」。
- 凭证镜像的落点是原生私有目录里的普通 `SharedPreferences`，理由写在
  `SiteCredentialStore.kt` 的类注释里；它必须与导出、备份路径保持隔离。
