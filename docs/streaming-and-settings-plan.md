## 子计划 A：网页自动保存、共享缓存与原生边下边播

状态：2026-10-22 已经用户逐项决策并确认设计闭环；P0–P8 均待实现、审查和验收。本节替代原 A1–A4 草案。前述设备基线沿用已有记录，本次设计整理没有重跑设备或发布验证。

### A1 目标、首版范围与后续范围

- 网页播放器保持默认播放入口；开关开启后，当前选中标签页的实际播放经过稳定身份确认，创建独立的“观看保存”记录。原生播放由用户主动发起。
- 首版自动保存仅支持能确定结束、能够建立稳定资源身份的 HLS VOD；支持 TS/fMP4、AES-128、`EXT-X-MAP`、init segment、相对地址以及受控 Range 输入。
- DRM、直播、无法还原稳定媒体身份的 MSE/blob、无法确认的剧集或表示形式，显示具体不支持原因；网页自身播放继续，不猜测或自动替换候选。
- 首版允许 WebView 播放与保存器各请求一次相同媒体。统一缓存复用发生在应用管理的下载、原生播放、转 MP4 和投屏之间，不宣称已经复用网页响应或节省网页播放流量。
- 未完成 HLS 支持原生边下边播和 seek；缺失分片由统一协调器按需获取。DLNA 只接受完整、经过校验的 HLS/MP4。
- 普通 MP4 Range 自动保存、直播录制、WebView 响应与保存器共用数据通道、部分缓存 DLNA，分别作为后续子计划，不混入首版完成标准。
- 手动嗅探下载与观看保存的管理入口、记录及删除权限分开；相同资源的字节、索引和后续能力共用。内容保留至手动删除；转 MP4 后的源 HLS 可按 A7 的所有权规则回收。

### A3 架构、数据权威与接口

```text
当前标签网页确认播放 ─┐
手动嗅探下载 ─────────┴→ 保存意图/所有者 → Android MediaResourceCoordinator
                                           ├─ 资源、表示形式和授权代次
                                           ├─ manifest/index 与分片文件
                                           ├─ 持久队列、优先级、进度
                                           ├─ 请求合并、单写入、引用和租约
                                           ├─ Media3 DataSource → 原生部分缓存播放
                                           ├─ 完整本地输入 → Transformer/Inspector → MP4
                                           └─ 完整 HLS/MP4 → 受限 DLNA relay
```

#### 单一权威

- Android 原生媒体服务负责资源索引、下载状态、队列、分片文件、所有者引用与租约；任务执行不依赖 Flutter 页面、Dart Timer 或 Activity 路由回调。
- Flutter 继续负责 AppSettings、界面、用户操作意图和其余应用数据。新媒体索引只有原生一个写入入口；既有 `media_tasks` 等若为兼容保留，只能是带原生 revision 的投影或迁移输入，不能与原生索引互相回写、竞争权威。
- 沿用 Pigeon 类型边界。新增状态快照、分页查询、命令和事件；不传整块视频、Cookie、Authorization、Web Storage 或任意可写文件路径。
- 下载、原生播放、导出和投屏复用同一套所有权/错误映射/进度规则。保留既有代理、VPN、TLS、受限地址、重定向及 fail-closed 策略。
- 共用视频缓存文件和索引，不要求 mmap/共享内存；不再把共享资源复制进另一份 SimpleCache。`.part` 与提交文件属于同一资源写入过程。

#### 逻辑模型

| 模型 | 必要字段/职责 |
|---|---|
| MediaAsset | 稳定 assetId、来源身份、剧目/集数身份、内容版本、首选可用输出、创建时间 |
| MediaRepresentation | representationId、assetId、清晰度、视频/音频轨道、编码、HLS VOD 类型、manifest 身份 |
| PlaybackEvidence | tab/frame/document/SPA 代次、活动媒体源、播放状态、稳定确认及失效原因 |
| MediaOwner | ownerId、manual/watch 类型、资源引用、暂停/删除意图、标题/集数及保存策略 |
| AuthorizationContext | 原生内部的来源页/profile 绑定、授权代次、有效性、允许刷新范围；敏感内容不出桥接 |
| HlsManifestSnapshot | 主/媒体清单、选定表示形式、ENDLIST、分片顺序、MAP/key/Range 关系、内容版本 |
| HlsResourceEntry | resourceId、相对文件身份、类型、sequence/byte-range、期望长度/校验器、临时/已提交状态 |
| TransferJob | 资源与所有者、优先级、排队序号、重试时间、执行 epoch、暂停原因、错误码 |
| MediaLease | playback/export/cast/download 类型、所有者会话、资源集合、存活证明与释放状态 |
| ExportArtifact | 独立 artifactId/catalogId、来源资源/输出配置、校验结论、可用本地文件或 SAF 身份、独立所有权 |

上述是契约模型，可合并物理表；落库前必须给出唯一键、事务边界和恢复规则。不能以表结构合并为由让两个运行时同时写同一索引。

#### 身份规则

- 区分显示去重、持久内容/表示形式身份与临时授权身份。`hostId/generation/candidateId` 是观测与授权上下文，不能直接充当跨页面重建后的唯一内容身份。
- 页面、frame、document、SPA 代次用于证明观测有效性；持久资源还必须有来源、剧目、集数、表示形式和内容版本约束。字段缺失或冲突时禁止自动创建，显示 unknown/具体原因并保留手动入口。
- 不通过剥离全部 HLS query 参数合并资源；`line`、episode、quality、audio 等选择信息必须保留。只允许经过验证的短期凭证字段旋转。
- 授权 URL 改变不等于内容相同。续接前验证 manifest、分片序列/Range、MAP/key、轨道配置和可用校验器；无法证明内容一致时保留旧资源，禁止拼接。
- 清晰度、音轨或内容版本变化创建独立 representation；旧记录按既定策略保留和补齐。

### A4 状态机、原子提交与进度

概念流程：

```text
observed → confirmed → queued → acquiring → playablePartial
                                      └→ 后台补齐 → complete → validating → mp4Ready
```

实现时分开保存以下维度，不能把可播、下载、授权和导出揉成一个互斥状态：

| 维度 | 状态与含义 |
|---|---|
| 观测 | observed/confirmed/revoked；只有 confirmed 能创建观看保存记录 |
| 下载 | queued/downloading/waiting/paused/completed/failed/cancelled，另附暂停/失败原因 |
| 可用性 | empty/partial/complete/invalid；partial 的可播范围单独表示 |
| 授权 | valid/refreshing/waitingExecution/reauthorize；执行环境不可用不能伪报为授权失败 |
| 导出 | none/queued/exporting/validating/ready/failed/cancelled |

- 下载原因至少区分 user/network/storage/system/authorization；UI 明确显示 `pausedByUser`、`pausedByNetwork`、`pausedByStorage`、reauthorize、unsupported 等可理解状态。
- 完整分片通过验证后原子发布。一个资源只允许一个有效写入者；下载器和原生播放器对同一分片的请求合并，取消一个消费者不影响仍有效的其他消费者。
- 未提交 `.part` 不作为完整分片提供；已有完整分片不重下。资源等待有界，取消可唤醒等待者，失败不会永久占槽或占文件锁。
- 原生播放所需 manifest 来自固定 VOD 快照，不能把“当前已缓存列表”冒充完整 VOD，不能提前写出 EOS；缺片必须通过协调器按需请求。
- 总大小未知时显示已下载字节、已完成/总分片及可用范围，不编造百分比。UI 进度合并推送，目标沿用现有约 250 ms 的刷新节奏；完成、暂停、错误立即刷新。持久化按提交/检查点进行，不逐字节写库。
- 暂停与取消保留已提交缓存；删除是显式解除 owner 并进行条件回收的另一操作。重启恢复以提交索引、执行 epoch 和原生任务事实为准，不采用易误排序的可变精度时间字符串。

### A5 队列、并发与交互策略

#### 并发与优先级

- 当前播放集另有 1 个高优先级资源任务；旧集后台补齐最多 3 个。应用管理的活跃下载资源去重后合计不超过 4 个，手动任务也接入这一预算，不能额外开不受限的下载池。
- 4 是媒体资源任务上限，不是 WebView 网络请求总数；首版网页有自己的播放请求。每个资源内的连接、缓冲和文件写入也必须有界，不因列表增长而增加常驻执行器。
- 优先级：原生播放/seek 急需分片 → 当前网页集顺序保存 → 最近切换旧集 → 其他旧集；手动任务复用或参与同一调度，遵守当前播放优先且不无限饿死已有任务。
- “最多 3 集”不是始终拉满。弱网、播放缓冲或资源紧张时减少/暂停旧集补齐；首版只能调节应用保存器，不能宣称已经直接控制 WebView 内部请求优先级。
- 队列不设固定集数上限；持久化分页读取、按需加载 UI。通过有限活动任务和缓冲控制内存；空间不足暂停接收/执行新内容并解释原因，不静默删除已有记录。

#### 行为表

| 事件 | 必须发生的行为 |
|---|---|
| 当前选中标签稳定确认播放 | 幂等创建/关联观看保存记录；不枚举下载整部剧或所有候选 |
| 切集 | 保留上一集缓存和记录；当前集获得优先槽位，旧集按后台策略排队 |
| 暂停/结束/离页/关标签 | 不删除记录；失去活动播放关联后按后台补齐开关决定是否继续 |
| 后台或隐藏标签开始播放 | 不创建新的观看保存记录；已有记录的后台任务独立处理 |
| 清晰度/音轨切换 | 新建独立资源/表示形式，旧资源继续按策略保留 |
| 再播旧集/手动下载同资源 | 复用已有资源，恢复或追加 owner，不复制字节、不重复下载 |
| 原生 seek 未缓存位置 | 提升缺片优先级，有界等待；超时显示缓冲或错误并保留断点 |
| 网络/空间/系统条件不满足 | 暂停相应请求，保留文件和记录，显示原因，满足条件后按策略恢复 |
| 用户强制停止应用 | 遵守停止；用户重新打开后读取持久状态恢复 |
| 删除一条记录 | 仅解除该 owner；其他 owner/租约和独立 MP4 保留 |

### A6 设置、入口与能力说明

设置继续集中在 AppSettings/SettingsRepository，新增字段缺失时兼容旧设置及备份。正式字段名可按项目命名规范确定，但含义固定：

| 设置 | 默认与语义 |
|---|---|
| 网页播放时自动保存 | 默认关闭；开启后才创建记录；关闭立即停止新建并暂停已有自动保存意图，手动任务继续 |
| 切集后继续后台补齐 | 默认开启，依赖总开关；关闭暂停旧集下载和旧集后台授权刷新，保留断点 |
| 允许蜂窝/计费网络自动保存 | 默认关闭；当前集与旧集的自动请求都遵守，不能因为网页正在蜂窝播放而额外下载 |
| 完整后转 MP4 | 按已确认的观看保存策略在完整校验后自动执行；复用既有导出配置与目录，不擅自改变手动下载的全局偏好 |

- 默认允许非计费 Wi-Fi；蜂窝和计费热点必须经用户明确允许。网络无法可靠判定时显示 unknown/等待，不当作免费网络。
- 下载网络限制与网页当前播放分开；缓存命中可读，缓存未命中仍必须遵守有效下载/授权策略，原生 DataSource 不能绕过暂停或流量设置。
- 关闭自动保存只暂停自动 owner；同资源如仍被手动 owner 请求，资源传输可以继续，UI 解释共享占用。停止/删除一个消费者不能中断其他有效消费者。
- 观看保存与媒体任务分开入口或分组，复用进度、暂停/恢复、批量管理、删除、原生播放、导出、播放列表和完整资源 DLNA 操作。
- 列表显示来源/剧目/集数/清晰度/音轨、部分可播范围、下载/导出状态、共享引用和暂停原因；点击受限操作时展示具体边界。
- 设置与诊断区分 configured/effective/observed/unknown；只打开诊断不能创建 WebView、主动刷新授权、播放媒体或发起网络任务。
- 采用子计划 B 的二/三级设置页面、单一滚动视口与虚拟列表，不恢复长玻璃面板或嵌套主滚动。

### A7 完整性、MP4、删除与 DLNA

- 对所选 VOD 的所有必需视频/音频、init/MAP、AES key 与 Range 资源完成下载及严格校验后，才进入 MP4 阶段；网页 ended、首片可播或字节进度达到某比例均不是完成证据。
- 复用现有 Media3 Transformer + Inspector、受限本地 DataSource、无网络/无隐式转码、`.part` 清理和样本/时间轴/EOS 校验，不回到手写样本封装链路。
- 以内容/表示形式和输出配置作为导出幂等键，手动 owner 与观看 owner 请求同一输出时只执行一次；导出持有源租约。
- MP4 校验并原子提交成功、独立索引可读后，观看保存记录切到可用 MP4。存在其他源 HLS owner 或播放/投屏/导出租约时保留 HLS；确认没有引用后才回收源分片。
- MP4 失败、输出空间不足、SAF 投递失败或输出不可读时保留源缓存与错误状态。不能在输出仅“创建了路径”时就回收 HLS；SAF 与本地文件的可用性/所有权分别确认。
- 已导出 MP4 的 catalogId 和生命周期独立；删除任务、观看记录或 HLS 不连带删除。移动文件保留目录身份，新文件占旧路径得到新身份。
- 清理使用持久 owner 引用与会话租约；崩溃恢复需要核对会话/执行 epoch，避免失效租约永久阻塞或把仍使用的文件删掉。回收与解除引用有事务/恢复日志，不能只依赖内存计数。
- DLNA 首版只对完整校验 HLS/MP4 开放；复用受限 relay、范围校验、会话授权和租约，结束后释放。SOAP 成功与接收端真实播放/seek 分别取证。

### A8 后台执行与自动重新授权

#### 执行边界

- 下载任务独立于 Flutter 路由与页面；退后台/锁屏依系统允许的执行机制继续，通知提供进度、暂停、继续、取消。
- 保留现有原生 WorkManager/续传能力作为迁移基础，先验证 HLS 全部子资源与授权场景；用户触发长传输与自动补齐按触发语义选择适用机制，不能仅凭开关就声称所有任务都符合 UIDT。
- 系统回收/时间或配额限制保留断点并显示 waiting/system 原因；不以长驻 Dart Timer 或绕过用户强制停止来维持下载。下载与转封装分别管理执行条件。

#### 重新授权流程

```text
请求失败且确定为授权失效
  → 复用有效授权/同身份已知新授权
  → 校验通过则恢复
  → 否则等待网络、后台策略及执行条件
  → 受限临时授权刷新 WebView 打开原播放页
  → 得到同身份新地址并验证内容/表示形式
  → 关闭刷新会话并恢复下载
  → 最终失败：reauthorize，保留断点，等待人工
```

- 旧集刷新受自动保存及后台补齐开关共同约束；蜂窝/计费限制同样适用，不允许“暂停下载但后台不断开网页”。当前集刷新遵守当前保存策略。
- 新增专用授权刷新用途/生命周期，复用原浏览 profile/cookie；不能把现有使用独立 profile 的 discovery/probe 直接改成共享 Cookie，也不能复用用户正看的 WebView 导航。
- 允许原页必要的站点脚本解析；禁止弹窗、跨站顶层导航、任意候选探索、广告枚举、独立文件下载和自动播放；拒绝权限申请、外部 intent、验证码代答等需要用户交互的行为。
- 原页允许的 CDN 子资源按既有网络/授权策略处理，不能把子资源请求当作跨站顶层导航来任意放行，也不能扫描全部剧集刷新。
- 绑定最初来源页、剧目、集数、清晰度、音轨和内容版本；新候选只属于当前刷新会话，不能污染用户当前标签的候选列表、播放会话或通知。
- 单独限制刷新会话并发、超时和重试次数；同一授权代次不得无限刷新。P5 实现前给出有界常量并覆盖超时/取消/renderer crash/重复触发/销毁测试。
- 同 profile 复用不等于无站点副作用；应用不能清理共享 Cookie/Storage、删除用户 profile 或导航用户当前标签。结束只销毁临时视图及自有桥接/监听。
- 必须实测无前台 Activity、退后台、锁屏及进程恢复后的创建与销毁条件。不允许通过自动拉起可见 Activity 强行满足条件；系统暂不允许时显示 waitingExecution，允许执行后继续，不能把未尝试伪报为重新授权失败。
- 验证码、登录失效、手势依赖、DRM、跨站跳转或媒体身份不确定时，自动阶段结束并进入 reauthorize；不换集、不重置、不清缓存。

### A9 旧任务与既有模块迁移

- P0 明确旧 Dart HLS、原生普通媒体后台下载、现有 `media_tasks`、原生 repository 和导出目录之间的映射；保留 taskId、catalogId、下载进度、标题/集数、来源、暂停意图及已导出资产。
- 已完整文件优先原地登记到原生资源索引，通过受限根目录校验后复用；不为统一目录而复制或重下载全部内容。旧目录可以作为只读已登记存储位置。
- 部分资源只有在 manifest/Range/校验器和授权身份能够验证时才续接；未知旧片保留，不擅自接到新表示形式上。
- 切换按“持久检查点 → 旧写入者停止并释放 → 导入/校验 → 原生接管 → 发布投影”执行；利用执行 epoch/文件锁阻止旧任务复活写入。

- Pigeon 变化同步生成 Dart/Kotlin/Swift，iOS 明确返回当前不支持边界，不宣称实现 Android 专属后台下载。修改现有 DTO 的“Dart 权威”注释必须伴随实际迁移和契约测试。

### A11 验收矩阵与闭环判据

| 类别 | 必测场景 | 合格证据 |
|---|---|---|
| 当前播放身份 | 广告、推荐、隐藏标签、旧 SPA、frame 更换、ABA/迟到结果、数量相同但内容不同 | 不创建错误记录；正确剧集、清晰度、音轨有确定性与真机对应证据 |
| 资源复用 | 自动/手动同源、签名刷新、不同轨道/清晰度、重复点击/重启 | 相同内容一份字节及一个写入者；不同表示形式不拼接 |
| 并发 | 当前集 + 多个旧集 + 手动任务、连续快速切集、弱网缓冲 | 应用活跃资源任务最多 4、旧集最多 3；前台优先、无无限并发或永久饿死 |
| 原生边下边播 | 慢速 VOD、起播、seek 未缓存、回看、EOS/最后样本 | 播放早于完整下载；缺片合并/有界等待；音画和时间轴正确 |
| 输入与校验 | TS/fMP4、AES-128、EXT-X-MAP、init、Range、AAC ADTS、多音轨起点、B 帧 | 样本数量、AAC AU、ASC/ADTS、PTS/CTTS/decode order、EOS/最后时长符合既有契约 |
| 后台与网络 | 退后台/锁屏/关页/重启、代理/VPN/重定向、Wi-Fi→蜂窝、计费热点、系统回收、强制停止 | 通知可控、策略立即生效、断点恢复、系统限制原因准确 |
| 自动授权 | Cookie/profile、同身份旋转、内容变化、403、原页自动解析、验证码/手势、无 Activity | 严格同资源才续接；等待执行不冒充失败；最终失败 reauthorize 且缓存保留 |
| 文件安全 | 越界路径、危险 URL、损坏分片、部分提交、重复进程写入、取消和 `.part` | 拒绝越界/错误输入；无未提交分片泄漏、无限等待或写入竞争 |
| 所有权 | 删手动/删观看、播放中删除、导出/投屏中删除、MP4 后回收、输出失败 | 其他 owner/lease 和独立 MP4 不受损；条件满足后可恢复回收 |
| 迁移 | 旧完整/部分任务、暂停意图、重复导入、旧写入者复活、迁移失败 | 任务/目录身份保留，无复制、无丢失、无双写和错误续接 |
| 内存/存储 | 大队列分页、多轮切集、反复 seek/刷新、空间不足、MP4 输出空间 | 记录增长不增加活动下载和临时 WebView 数；受控缓冲，无持续泄漏或 OOM |
| DLNA | 完整 HLS/MP4、未完整拒绝、接收端 seek、断连和结束 | 实际接收端证据；授权/租约释放；SOAP 成功不代替播放 |
| UI/设置 | 两开关、蜂窝策略、进度、空/错/unknown、旧设置/备份、高质量玻璃长列表 | 状态与有效策略一致，无嵌套主滚动，长列表末尾可达 |

验证顺序：定向契约/单测 → `make check` → Kotlin/host contract/Pigeon 与 debug 构建 → 受保护定向集成 → `make acceptance DEVICE=<当前有效端点>` 的 L3 → 发布所需 L4/签名/CI。端点按项目规则一次预检/一次恢复；不在计划中写死个人设备端口。

设计闭环只表示产品选择、资源所有权、失败恢复及验收门槛一致；P0–P8 任一实现/审查/设备/发布门槛缺证据都必须保留未完成状态。
