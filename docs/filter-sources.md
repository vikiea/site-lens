# 过滤规则源与装载边界

设置内的开关对应每一个订阅源，包括内置和自定义订阅。关闭源保留下载缓存，重新启用时无需重新下载。批量刷新仅处理已启用源。选择在下一次导航或刷新页面时生效；当前文档继续使用已绑定快照。

此前的“规则较大，暂不加载”来自应用对Pigeon内联消息设置的512 KiB预算，不是规则本身不兼容，也不是已测量的Android系统硬限制。它使部分已下载、已编译的内置订阅无法装入原生WebView，导致请求过滤和页面过滤没有使用预期规则。

大规则现在写入应用私有目录的内容寻址文件，仅通过通道传递文件标识和字节数。Android后台校验路径、长度、SHA-256及JSON，完整成功后切换内存规则；页面脚本先注册新句柄，再移除旧句柄。网络拦截使用完整编译 bundle；页面元素规则也保留域名和例外语义，document-start 配置设有 4 MiB 独立脚本预算，超过时拒绝本次页面注入、保留上一有效 hook 并显示诊断，避免把大订阅全部复制到每个 WebView 文档。任何装载失败保留上一有效快照并显示独立诊断，不能显示为宿主不支持。

输入订阅仍限制10 MiB，编译后payload限制32 MiB和30万条规则，避免失控订阅占满内存。小规则继续内联。应用只支持编译器已实现的Adblock/uBlock语法子集；不支持的语法计入诊断，装载成功不代表完整uBlock兼容。

关闭或删除源时，数据库选择与合并快照在同一事务内更新。若剩余源损坏且没有匹配选择的有效历史bundle，操作失败并恢复原选择和内存规则。订阅配置URL保持稳定，镜像实际下载地址仅记录在源快照中。

本批Android定向证据包括大规则文件装载、越界和损坏拒绝、导航握手，以及数据库备份恢复。iOS保持现有过滤能力边界；本批没有新增iOS网络过滤或设备验收证据。
